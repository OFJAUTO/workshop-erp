# Workshop ERP

ERP for a luxury car workshop in Dubai (about 45 users). The owner is not a developer: explain steps in plain language and say exactly what to click. Build one phase at a time and stop for approval after each.

## Read first

- `docs/workshop-erp-blueprint.md` - the full specification and agreed decisions.
- `docs/phase-1-decisions.md` - answers that shape the build (tablets, VIP privacy, plates, retention).
- `docs/phase-2-spec.md` - authoritative Phase 2 spec (gate-in, approval page, job cards, floor board, gate-out); overrides the blueprint on those topics.
- `docs/later-phases-notes.md` - owner notes for phases 4 to 6 (quotation rules, parts flow, profit per invoice).
- `docs/workshop-erp-dashboard-design (1).html` - the look: white, black, grey; colour only for timing.

## Stack

- Next.js 16 (App Router, `src/`), React 19, Tailwind v4, TypeScript. Light theme only.
- Supabase: Postgres + Auth + Storage. Access rules live in the database (row level security), not only in the UI.
- Hosting: Vercel (project workshop-erp). Live address: https://erp.ofjauto.com (the vercel.app address redirects there). Code: private GitHub repository github.com/OFJAUTO/workshop-erp; every push to `main` deploys automatically.
- Secrets in `.env.local` (never committed). Keys: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_DB_PASSWORD`, `SUPABASE_ACCESS_TOKEN`, `CRON_SECRET` (the same value must exist in Vercel for the hourly `/api/cron/housekeeping` job).
- Live updates use Supabase Realtime (`LiveRefresh` component); tables are in the `supabase_realtime` publication. Two project-specific lessons: the browser client must call `supabase.realtime.setAuth(session.access_token)` before subscribing (otherwise it joins as `anon` and RLS hides everything), and server-side filters on uuid columns (`id=eq.<uuid>`) were never registered, so subscriptions are unfiltered and matched in the browser. Subscribing to a table that is not in the publication silently breaks the whole channel. Notifications: `src/lib/notifications.ts` (`notifyStaff`, `notifyRoles`, `NOTIFICATION_TYPES`).
- Logins: `staff.login_type` is `password`, `pin` or `both` (owner sets it). Devices (`devices.kind` shared/personal) are registered by the owner on the device at `/tablet/register`; the proxy signs out handheld sessions whose device was removed.

## Conventions

- Every business table has `created_at/by`, `updated_at/by`, an audit trigger (`write_audit_log`) and a no-delete trigger. Mark records inactive instead of deleting.
- Permissions: `src/lib/roles.ts` mirrors the SQL policies. Pages call `requireStaff()` or `requirePermission()` from `src/lib/auth.ts`.
- `createClient()` (server) acts as the logged-in person. `createAdminClient()` bypasses rules: server only, used for logins, PIN checks, tablet registration, settings reads.
- PC login: email + password (form post to `/api/auth/login`). Handheld login: name + 4-digit PIN on registered devices only (`devices` table, `erp_device` cookie). PIN login issues a session through an admin-generated magic link verified server-side. Password setup links: `setup_links` table, `/auth/setup/[token]`, 24 h, used only when a password is saved.
- Setup/password links are generated by the owner and sent on WhatsApp; no email sending is configured.
- Forms: client components using `ActionForm` (`src/components/forms.tsx`); server actions return `{ error, success, values }`.
- Plain words on screen, 44px minimum touch targets, one-tap choice buttons instead of drop-downs where the list is short.
- Standing rule: the result of a click appears at or next to the thing that was clicked, or in a centre window (`SendLinkDialog`). Never somewhere the person has to scroll or search for.
- Standing rule for every customer link (approval, inspection report, later quotations and estimates): a written WhatsApp message from a template in Settings, and a public page whose preview shows the logo, a title and a one-line description (`customerPageMetadata` in `src/lib/customer-pages.ts`; the path must be in `PUBLIC_PREFIXES` in `src/proxy.ts`).
- Standing rule: every box where people type words has spell check on, in English (`Input`/`Textarea` in `src/components/ui.tsx` do this; keep it for anything built later). Browsers do not accept a site word list, so car terms are added to the device dictionary by each person.
